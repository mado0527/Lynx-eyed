# 専用管理画面の実装・モック比較（2026-10-08）

## 参照とURL

目標は最初に添付された102054・102101（ダッシュボード）、102204（ログイン）の画像。102249・102304・102313は修正前の標準adminの画面として確認した。提供済み「モックアップ.zip」の `Admin.tsx` と `Login.tsx` も読んだ。固定人数・利用率・延べ利用回数・月別配列・モックの独自認証は移植していない。

- `/management/login/`：独立した管理者ログイン。
- `/management/`：独立した管理者ダッシュボード。
- `/management/logout/`：CSRF保護されたPOSTログアウト。GETは405。
- `/admin/`：既存のデータ登録・編集画面を維持。専用画面の「DB設定」からアクセス可能。接続情報や認証情報を編集する画面ではない。
- `/device-management/`：既存の権限付き端末画面。専用画面からの場所指定を引き継ぎ、カメラをその場所に絞る。端末モデルには場所項目がないため、端末一覧は閲覧可能な全端末であることを明示。
- `/login/` は `/management/login/` へ転送し、nextを引き継ぐ。`/admin/login/` も同じ独立テンプレート・管理者認証を使用。DB設定のPOSTログアウト後は専用ログインへ移動し、再認証後は `/admin/` へ戻る。トップの管理者リンクは `/management/?location=...`。

専用2画面は完全なHTMLテンプレートで、adminのbase/index/loginを継承しない。標準adminの青いヘッダー、モデル一覧、操作履歴、ユーザーツールは専用画面に含めていない。

## データの意味

**現在の利用人数**：選択場所の現在時刻以前の最新CrowdLog。日時が同じ場合は最大log_idを採用。古い計測も最終計測日時を併記し、リアルタイム計測と断定しない。記録がなければ未計測、記録された0人は0。

**平均利用率**：選択月のCrowdLog.crowd_rateのうちNULLではない有限の保存値の算術平均。上段と月別指標は同じ月・同じ方法。対象月・採用件数を表示し、現在定員で過去の保存率を再計算しない。対象月の記録がなければ未計測、人数記録はあるが有効な率がなければ算出不可。

**日別の青い棒**：日本時間の各日について、人数合計÷その日の記録件数。未計測日には棒を描かず、0人の計測がある日は基線の2px棒。日付ラベルはスマホで間引く。マウス・タップ・キーボードで各日/平均人数・未計測の吹き出しを表示できる。

**最大利用人数**：選択月の実測人数の最大値。**延べ利用回数**：瞬間的な人数ログだけでは同じ人の重複を区別できないため未対応。人数の単純合計やMonthlyReport.total_creationsで代用しない。

対象月の期間は日本時間の月初00:00以上・翌月初00:00未満。当月は現在時刻まで。集計の細かい説明・日別表はレポートカード内の閉じた折りたたみへ配置。場所選択はログイン経由・月切替・端末画面の戻るでも維持。

## 認証・操作の権限

認証はDjangoのAuthenticationForm/LoginView/LogoutViewを再利用。既存Djangoユーザーのハッシュ化されたパスワードを使用し、旧AdminInfoモデルやモックの固定/平文認証は使わない。参照：[Django認証ドキュメント](https://docs.djangoproject.com/ja/5.1/topics/auth/default/)。

| 操作 | 条件 |
|---|---|
| 管理者ログイン | 有効なDjangoユーザー、is_staff=True |
| ダッシュボード・月/場所の切替 | 有効なstaff、view_locationmasterとview_crowdlogの両方 |
| カメラの表示 | view_camerainfo。なしの場合はカード内に閲覧権限なし、情報は取得しない |
| 端末画面へのボタン・画面 | view_deviceinfoまたはview_camerainfo。既存画面で各種類の閲覧権限も個別確認 |
| 端末画面の場所指定 | view_locationmasterも必要。権限なし/不正な場所は403 |
| データ管理 | staffと既存のadmin権限制御。モデルごとの閲覧・追加・変更・削除は既存Django adminが判断 |
| 通知変更 | 未実装。無効チェックボックス、保存処理なし |
| ログアウト | CSRF検証を通るPOST。セッションを破棄してトップへ。外部リダイレクト指定は使用しない |

未ログインは専用ログインへ、ログイン済みの一般ユーザー・権限不足staffは403。ログインのnextはDjangoの安全なリダイレクト検証を使用。通常ログインによるセッション/last_login更新とログアウトはDjango標準の動作だが、検証は一時DBで行った。
